# 本地程序

已实现 main.py：提供页面、健康接口、设置接口、聊天流、停止与记录恢复。运行 python -m app.main 在 127.0.0.1:8000 启动服务。
目前只支持源码运行；网页文件位于源码仓库 web/，未制作包含资源的独立安装包。

模块分工：
- main.py：启动 FastAPI、提供网页和接收请求。
- model.py：调用 DeepSeek，将回答逐段传回。
- storage.py：原子替换写入 .env、会话 JSON 和当前选择文件；列出历史并从第一条问题生成标题，消息保留角色、编号、状态和关联问题。
- context.py：按本机配置只读加载原项目 10 份材料，读取已保存的应用计算机断点，加入实际能力说明，保存请求材料快照；原文范围见 docs/teaching-context.md。

一次聊天：读取原文并准备教学上下文与完整问答 → 保存材料快照、用户消息和待生成记录 → 调用模型 → 逐段传回 → 保存回答 → 通知网页保存结果。读取或保存失败不调用模型。
main.py 用一个生成任务处理当前回答，队列只负责把增量传给网页；停止或断开连接时取消任务并保存片段。测试可注入临时资料路径和模拟模型，不读取真实密钥。
中断的回答标记为未完成，不伪装成完整回答。

会话管理：GET /api/conversations 列出历史，POST 同一路径新建，POST /api/conversations/{id}/select 切换。新建、切换、聊天和重试保存都带页面当前 conversation_id，服务核对后才操作，拒绝过期窗口写入。当前选择保存至 data/current-conversation.json；旧版没有此文件时沿用最近修改会话的恢复方式。

切换成功后才替换内存中的当前会话，生成中或保存失败时拒绝切换。新建前保存旧选择，新文件与新选择依次落盘；若新文件已保存而选择写入失败，保留旧选择，列表可能多出一个可稍后打开的空白对话。打开历史中未完成的回答时将其标记中断。没有数据库或多会话并行生成。

已实现断点流程：读取旧断点和当前对话 → 请求模型整理四段 Markdown 草稿 → 用户编辑确认 → 原子保存并展示。breakpoints.py 负责提示装配、草稿/记录格式及文件读写；main.py 提供读取、整理、取消、保存和来源接口。草稿保留在服务内存，保存核对草稿编号、旧版本和消息位置，失败不覆盖旧记录。
格式正确不代表学习判断正确，用户仍能纠正。

一个本地服务同时提供网页和接口，默认只监听本机。密钥由后端读取，不写进聊天或返回给模型作为对话内容。
具体接口和数据字段在实现相应功能时确定，不提前创建空实现。
